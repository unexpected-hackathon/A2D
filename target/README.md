# target · 피공격 서버 (가상 채용·인재 매칭 플랫폼)

담당: 김성원 · 커밋 scope: `target`

> **경고: 일부러 취약하게 만든 서버다.** 노트북의 시연 환경이나 격리된 네트워크에서만 띄우고, 공인 IP나 공개 도메인으로 노출하지 않는다. 심어 두는 개인정보는 모두 가짜 데이터로 만든다.

A2D가 점검하는 시연 대상. 보안 전담 인력이 부족한 소규모 채용 플랫폼·채용관리 SaaS(ATS)처럼 꾸미고, 설정이 잘못된 지점을 일부러 심는다. 지원자·기업회원·채용 공고 데이터는 모두 가짜로 만든다. 시연에서는 점검 → 세 가지 조치 → 재점검으로 안전 점수가 오르는 흐름을 보여 준다.

## 가상 서비스 구성

| 자산 | 역할 | 중요도 예시 |
| --- | --- | --- |
| `www` | 채용 공고와 지원서 작성 화면 | 5: 개인정보 입력 |
| `api` | 지원자·지원 이력 조회 API | 5: 개인정보 응답 |
| `admin` | 채용 담당자 관리 화면 | 4: 관리자 도구 |
| `staging` | 개발·테스트 채용 서비스 | 3: 테스트 자산 |
| 파일 저장소 | 가상 이력서·증빙 파일 보관 | 5: 지원자 파일 |

## 기본 시연 결함

[docs/A2D_점검점수설계.md](../docs/A2D_점검점수설계.md)와 [채용 플랫폼 필요 점검리스트](../docs/research/A2D_채용플랫폼_필요점검리스트.md)를 기준으로 결함을 맞춘다. 번호는 공식 설계의 #1\~#34를 쓴다. A2D가 시연용으로 심어 둔 결함을 100% 찾는 것이 목표다(PRD 성공 지표).

기본 시연 프로필에서는 아래 세 결함만 활성화한다. 세 결함을 모두 찾은 뒤 `#16 API 인증 적용 → #8 백업 제거 → #18 관리자 접근 제한`을 수행하면 발견이 모두 해결되어 안전 등급이 F에서 D 이상으로 오른다. 실제 "오늘 할 일" 순서는 안전 점수 상승 폭을 계산한 코드가 정한다.

| 점검 번호 | 기본 활성 결함 |
| --- | --- |
| #8 | 웹 공개 경로에 남은 가상 지원자·이력서 백업 파일 |
| #16 | 인증 없이 가상 지원자 이메일·전화번호를 한 번 반환하는 승인된 더미 API |
| #18 | 외부에서 열리는 채용 담당자 관리자 로그인 화면 |

## 항목별 검증 결함

아래 결함은 각 점검의 탐지와 해결 처리를 검증하는 별도 프로필에서 하나씩 켠다. 기본 시연에서는 비활성화해 세 가지 조치 뒤에도 긴급·높음 발견이 남는 상황을 막는다.

| 점검 번호 | 채용 플랫폼 결함 예시 |
| --- | --- |
| #9 | 열린 `/.env`, `/.git/HEAD` |
| #11 | 지원서 처리 오류에서 보이는 스택·서버 경로·DB 오류 |
| #12 | 프런트엔드 JS에 심은 가짜 비밀키 형태 |
| #14 | 목록이 공개된 시연용 가상 이력서 저장소 |
| #17 | 인증 없이 열리는 API 문서(`/swagger`, `/openapi.json`) |
| #19 | 외부에서 열리고 디버그 표시가 있는 `staging`·`dev` 하위 도메인 |
| #23·#25 | 버전이 드러나는 취약·지원 종료 서버 소프트웨어 |
| #28 | 자체 서명 또는 곧 만료되는 인증서 |
| #30·#31 | 지원·로그인 화면의 보안 헤더와 쿠키 속성 누락 |
| #34 | RLS가 꺼진 시연용 Supabase 또는 공개된 Firebase Realtime DB 구조 |

나머지 1차 점검 항목에 맞출 결함은 PRD 미결 사항에서 정한다. 모든 결함 프로필에는 "고친 상태"로 바꾸는 방법(설정 토글 등)을 함께 만든다.
