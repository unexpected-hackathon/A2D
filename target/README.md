# target · 피공격 서버 (가상 여행 플랫폼)

담당: 김성원 · 커밋 scope: `target`

> **경고: 일부러 취약하게 만든 서버다.** 노트북의 시연 환경이나 격리된 네트워크에서만 띄우고, 공인 IP나 공개 도메인으로 노출하지 않는다. 심어 두는 개인정보는 모두 가짜 데이터로 만든다.

A2D가 점검하는 시연 대상. 보안팀 없는 여행 스타트업의 서비스처럼 꾸미고, 설정이 잘못된 지점을 일부러 심는다. 시연에서는 점검 → 세 가지 조치 → 재점검으로 안전 점수가 오르는 흐름을 보여 준다.

## 심을 결함

[docs/A2D_점검점수설계.md](../docs/A2D_점검점수설계.md)의 1차 점검 항목과 하나씩 맞춘다. 번호는 그 문서의 #1\~#34를 쓴다. A2D가 심어 둔 결함을 100% 찾는 것이 목표다(PRD 성공 지표).

| 점검 번호 | 결함 예시 |
| --- | --- |
| #8 | 웹 루트에 방치된 `backup.zip`, `db.sql` |
| #9 | 열린 `/.env`, `/.git/HEAD` |
| #11 | 스택 트레이스가 보이는 오류 페이지 |
| #16 | 인증 없이 회원 이메일·전화번호를 돌려주는 조회 API |
| #17 | 인증 없이 열리는 API 문서(`/swagger`) |
| #18 | 외부에서 열리는 관리자 로그인 화면 |
| #28 | 자체 서명 또는 곧 만료되는 인증서 |
| #30 | 보안 헤더 누락 |
| #23 | 버전이 드러나는 구버전 소프트웨어 |
| #19 | 외부에서 열리는 `staging`·`dev` 하위 도메인 |

나머지 1차 점검 항목에 맞출 결함은 PRD 미결 사항에서 정한다.

결함마다 "고친 상태"로 바꾸는 방법(설정 토글 등)도 함께 만든다. 시연에서 조치 후 재점검에 쓴다.

## 파일 배치

`.gitignore`에 걸리는 결함 파일(`.env` 등)은 `target/planted/` 아래에 둔다. 이 경로만 예외로 추적한다.

## 실행

스택이 정해지면 띄우는 방법과 시연용 도메인(로컬 DNS) 설정을 적는다.
