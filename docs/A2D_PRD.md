# A2D PRD

Oct 31, 2026 · 김강현

**이 문서는 A2D가 11월 1일 13시 제출 시점에 무엇을 해야 하는지 정한다.** 팀이 구현 중 범위를 판단할 때 기준이 되며, 배경과 상세 설계는 [A2D_기획서.md](A2D_기획서.md)와 [A2D_상세설계.md](A2D_상세설계.md)에 있다.

## 1. 개요

**A2D(Attack to Defense)는 보안팀이 없는 회사가 인터넷에 무엇을 얼마나 위험하게 노출하고 있는지 매일 알려 주는 외부 노출 점검 서비스다.** 공격자가 약한 고리를 찾는 방법으로 침입 없이 점검하고, 점수 하나와 "오늘 할 일 3가지"를 돌려준다. 이름은 읽으면 aid(도움)이고, 오늘 할 일 3가지가 그 응급처치다.

| 항목 | 내용 |
| --- | --- |
| 배경 | 2026년 10월 금융·항공·여행·대학 연쇄 침해는 노출 API, 관리도구, 방치된 파일 같은 외곽 접점에서 시작됐고, 공격자는 AI 자율 침투 도구로 이를 전수 탐색했다 |
| 해결할 문제 | 보안팀이 없는 조직은 자기 외부 노출 자산을 모르고, 점검은 연 1회이며, 결과를 읽어도 무엇부터 고칠지 모른다 |
| 해커톤 주제 | 02 AI 기반 정보보호 서비스 |
| 제출 기준 | 2026년 11월 1일 13:00 최종 커밋. 그 뒤 기능 추가는 규정상 불가 |
| 팀 | 김강현(AI·기획·발표), 김성원(백엔드·데브옵스), 정인호(프런트엔드) |

## 2. 목표와 성공 지표

**제출 시점의 목표는 "발견 → 응급처치 리포트 → 조치 → 재점검 → 점수 하락" 한 흐름이 가상 여행 플랫폼에서 끝까지 동작하는 것이다.** 아래 목표값은 팀이 정한 초기값이며, 모두 시연 환경에서 측정한다.

### 목표

1. 보안 비전문가가 도메인 등록 한 번으로 외부 노출 자산과 위험을 파악한다.
2. 리포트를 읽고 바로 조치할 수 있다.
3. AI가 없는 취약점을 지어내지 않는다.
4. 점검이 대상 서비스를 해치지 않는다.

### 성공 지표

| 지표 | 목표값 | 측정 방법 |
| --- | --- | --- |
| 심어 둔 결함 탐지율 | 가상 여행 플랫폼의 MVP 대상 결함 100% | 심어 둔 결함 목록과 발견 목록 대조 |
| 오탐 | "확인됨" 등급 오탐 0건 | 결함을 고친 뒤 재점검해 남는 발견 확인 |
| 근거 검증 통과율 | 리포트에 나간 문장 100%가 발견과 연결 | 근거 검증 로그 |
| 점검 시간 | 등록부터 리포트까지 5분 이내 | 시연 환경에서 3회 측정 |
| 조치 효과 | 오늘 할 일 3가지를 고치면 조직 등급이 "심각"에서 "주의" 이하로 | 조치 전후 재점검 |
| 요청 부하 | 대상 호스트당 초당 2건 이하, 점검 1회 300건 이하 | 가드 층 감사 기록 |
| 이해 가능성 | 팀 밖 비전공자 1명이 리포트만 보고 조치 3개를 설명할 수 있다 | 대회 기간 중 동료 교육생 1명에게 확인 |

## 3. 사용자와 사용자 스토리

**대표 사용자는 보안팀이 없는 여행 스타트업의 IT 담당자 한 명이다.** 대학·공공기관 담당자는 확장 대상이다.

| 페르소나 | 상황 | 원하는 것 |

| IT 담당자 (주 사용자) | 개발과 서버 운영을 겸임. 도메인·테스트 서버·위탁 서비스가 늘어남 | 무엇이 노출됐고 오늘 무엇부터 고칠지 알고 싶다 |
| 대표·경영진 (보조 사용자) | 보안 용어를 모름. 보안 투자 여부를 결정 | 우리가 얼마나 위험한지, 조치로 나아졌는지 한 장으로 보고 싶다 |

## 4. 기능 요구사항

**P0는 제출 시점에 반드시 동작해야 하고, P1은 시간이 남을 때 넣는다.** 시간이 모자라면 질의응답(FR-12) → 자산 지도(FR-14) → 점검 11종을 7종으로(FR-03) 순서로 덜어낸다. 점검 항목과 점수 공식의 세부는 [A2D_상세설계.md](A2D_상세설계.md)를 따른다.

| ID | 기능 | 우선순위 | 수용 기준 | 담당 |
| --- | --- | --- | --- | --- |
| FR-01 | 도메인 등록과 소유권 확인 | P0 필수 | DNS TXT 레코드가 확인되기 전에는 어떤 점검도 시작되지 않는다 | 김성원 |
| FR-02 | 자산 발견 5종 (하위 도메인, 웹 서비스, 기술 식별, API 문서, 관리 경로) | P0 필수 | 가상 여행 플랫폼에 있는 자산이 모두 목록에 나타난다 | 김성원 |
| FR-03 | 비침습 점검 11종 (C-01, 02, 04, 05, 06, 07, 09, 10, 13, 15, 16) | P0 필수 | 항목마다 판정 기준에 맞게 발견·확실성·가린 증거를 저장한다 | 김성원 |
| FR-04 | Attack 에이전트의 추가 점검 | P0 필수 | 기본 점검 결과를 보고 허용된 도구만 호출하며, 예산(도구 20회, 요청 300건, 5분) 안에서 끝난다 | 김강현 |
| FR-05 | 위험 점수 계산 (발견·자산·조직, 등급) | P0 필수 | 기획서 공식과 같은 값이 나오고, 화면에서 요소별 값을 볼 수 있다 | 김성원 |
| FR-06 | 오늘 할 일 3가지 선정 | P0 필수 | 고쳤을 때 조직 점수가 가장 많이 내려가는 순서로 코드가 고른다. LLM은 순서를 바꾸지 못한다 | 김성원 |
| FR-07 | Defense 에이전트의 응급처치 설명 | P0 필수 | 항목마다 제목, 왜 위험한가, 예상 피해, 조치 방법, 예상 조치 시간을 비전문가 언어로 낸다 | 김강현 |
| FR-08 | 근거 검증 | P0 필수 | 발견 ID와 연결되지 않은 문장은 삭제되고, 화면에 "근거 검증 통과 n/n"이 표시된다 | 김강현 |
| FR-09 | 재점검 | P0 필수 | 버튼 하나로 같은 점검을 다시 실행하고, 고친 발견은 "해결됨"으로 바뀐다 | 김성원 |

| FR-15 | 새 노출 알림 (대시보드 안) | P1 여유 시 | 재점검에서 새 자산·새 발견이 나오면 대시보드 상단에 알림이 뜨다 | 정인호 |
| FR-16 | 감사 기록 | P0 필수 | 모든 도구 호출의 시각, 도구, 인자, 결과, 거부 사유를 화면에서 볼 수 있다 | 김강현 |

## 5. 화면 요구사항

**화면은 네 개이고, 대시보드 첫 화면에서 점수와 오늘 할 일 3가지가 스크롤 없이 보여야 한다.** 모든 화면은 한국어이고, 등급은 색과 함께 글자(심각·위험·주의·양호)로도 표시한다.

| 화면 | 반드시 보여줄 것 | 사용자 행동 | 관련 요구사항 |
| --- | --- | --- | --- |
| 1. 등록 | 도메인 입력란, 등록할 TXT 레코드 값, 확인 상태, 점검 범위와 안전 원칙 안내 | 도메인 입력, 소유권 확인, 점검 시작 | FR-01 |
| 2. 대시보드 | 조직 점수와 등급, 오늘 할 일 3가지, 자산 목록(또는 지도), 점검 진행 상태, 새 노출 알림 | 항목 선택, 재점검 | FR-02\~06, FR-09, FR-14, FR-15 |
| 3. 응급처치 리포트 | 항목별 쉬운 설명·예상 피해·조치 방법·예상 시간, 근거 검증 표시, 접힌 기술 근거(증거, 점수 요소, CVE), 질문 입력란 | 근거 펼치기, 질문하기 | FR-07, FR-08, FR-11, FR-12 |
| 4. 기록 | 점수 추이 그래프, 점검별 변화(해결됨·새 발견), 감사 기록, 내보내기 버튼 | 기록 확인, 한 장 요약 내보내기 | FR-10, FR-13, FR-16 |

### 공통 규칙

- 기술 용어는 기본 화면에 두지 않고 접힌 근거에만 둔다.
- 확실성 등급(확인됨·가능성·확인 필요)을 모든 발견 옆에 표시한다.
- 시연 영상 녹화를 위해 1080p 화면에서 글자가 판독되어야 한다.

## 6. AI 요구사항

**AI는 Attack·Defense 두 에이전트로 나뉘고, 둘 다 팀이 만든 Python 함수 도구만 호출할 수 있다.** 점검 실행, 점수, 오늘 할 일 선정은 코드가 맡는다.

| 항목 | 요구사항 |
| --- | --- |
| 모델 | Qwen3-8B(오픈 가중치, Apache 2.0)를 주최 측 GPU 서버(NVIDIA L4, 23GB)에서 vLLM으로 서빙한다. 문맥 길이는 8천\~1만 6천 토큰 |
| Attack 에이전트 | 기본 점검 결과를 보고 추가 점검을 고른다. 점검 도구 7개만 쓰고, URL이 아닌 자산 ID만 넘긴다 |
| Defense 에이전트 | 오늘 할 일 3가지를 쉬운 말로 설명하고 질문에 답한다. 조회 도구 6개만 쓰고 점검 권한은 없다 |
| 출력 형식 | 리포트는 submit\_report 도구로 정해진 JSON 항목을 제출한다. 항목마다 발견 ID가 1개 이상 필수 |
| 근거 검증 | 발견 ID 존재, 자산·점수·조치 시간 일치, CVE는 증거에 있는 것만, 가이드에 없는 명령어 금지. 실패하면 한 번 더 요청하고, 다시 실패하면 기본 리포트 문장으로 바꾼다 |
| 입력 최소화 | LLM에는 발견 ID, 항목 ID, 자산 별칭, 점수 요소, 가린 증거(200자 이내)만 보낸다. 응답 원문과 개인정보는 보내지 않는다 |
| 프롬프트 주입 대비 | 점검 대상 응답은 "읽기만 하는 데이터"로 표시하고, 지시를 따르더라도 가드 층이 허용되지 않은 호출을 막는다 |
| 품질 확인 | 착수 초기에 발견 5건으로 한국어 설명 품질을 확인하고, 부족하면 프롬프트와 조치 가이드를 보강한다 |

도구 13개의 입출력과 가드 규칙은 [A2D_상세설계.md](A2D_상세설계.md)의 "도구 호출 설계"를 따른다.

## 7. 비기능 요구사항

**가장 중요한 비기능 요구사항은 안전이다. 소유권을 증명한 대상만, 읽기 전용으로, 느리게 점검한다.**

| ID | 분류 | 요구사항 |
| --- | --- | --- |
| NFR-01 | 안전 | 소유권이 확인된 도메인과 그 하위 자산만 점검하고, 다른 도메인으로 가는 리디렉션은 따라가지 않는다 |
| NFR-02 | 안전 | GET과 HEAD만 쓴다. 쓰기 요청, 로그인 시도, 입력값 조작, 번호를 바꿔 가며 반복 조회는 기능 자체가 없다 |
| NFR-03 | 안전 | 대상 호스트당 초당 2건, 점검 1회 300건, 요청마다 10초 제한. 점검은 언제든 중지할 수 있다 |
| NFR-04 | 안전 | 모든 요청에 A2D 점검임을 밝히는 User-Agent를 붙인다 |
| NFR-05 | 개인정보 | 응답은 앞 512바이트만 저장하고 이메일·전화번호는 가려서 저장한다. 시연 데이터는 모두 가상 데이터다 |
| NFR-06 | 개인정보 | 점검 결과와 LLM 추론은 주최 측 GPU 서버와 팀 환경 밖으로 나가지 않는다 |
| NFR-07 | 성능 | 등록부터 리포트까지 5분 이내, 대시보드는 3초 이내에 표시된다 |
| NFR-08 | 가용성 | LLM이 응답하지 않거나 근거 검증에 두 번 실패해도 점검·점수·기본 리포트는 동작한다 |
| NFR-09 | 추적성 | 모든 도구 호출과 거부가 감사 기록에 남는다 |
| NFR-10 | 제출 규정 | 저장소는 Public, API 키·비밀번호는 커밋하지 않고 .env.example로 대체한다. README에 설치·환경설정·실행 명령을 적는다 |

## 8. 범위 밖

**제출 버전은 한 조직이 가상 여행 플랫폼을 점검하는 흐름 하나만 다룬다.** 아래는 만들지 않고 로드맵에 둔다.

- 회원가입, 로그인, 결제, 여러 조직 관리
- 실제 외부 도메인 점검
- 침투, 공격 코드 실행, 계정 추측 등 읽기 전용을 넘는 점검
- 클라우드 계정·OAuth 앱 권한·위탁 연결 점검
- 점검 항목 C-03, 08, 11, 12, 14, 17 (디렉터리 목록, 로그인 평문 전송, 쿠키 속성, CORS, 지원 종료 SW, 메일 위조 방지)
- 메일·메신저 알림, 정해진 시간에 자동으로 도는 정기 점검 (제출 버전은 재점검 버튼으로 대신)
- 자동 조치. A2D는 권고만 하고 설정 변경은 담당자가 한다

## 10. 미결 사항과 위험

**가장 큰 미결 사항은 2차 심사에서 시연 영상이 라이브 시연으로 인정되는지다.** 가이드는 2차 발표에 라이브 시연 3분 이상을 요구하고, 시연을 하지 않으면 기술 완성도가 0점이다.

### 미결 사항

- [ ] 운영진 확인: 2차 심사에서 시연 영상이 라이브 시연으로 인정되는지, GPU 서버를 유지할 수 있는지
- [ ] 운영진 확인: AI 코딩 도구와 AI로 만든 문서의 외부 자원 기재 방법
- [ ] 자산 중요도 기본값 규칙과 점검 항목별 표준 조치 시간표
- [ ] 오프라인 취약 버전 목록에 넣을 제품 (시연 환경 기준 10개 안팎)
- [ ] 가상 여행 플랫폼에 심을 결함 목록을 FR-03의 11종과 맞추기
- [ ] 외부 자원 표: Qwen3-8B(Apache 2.0), vLLM, Pydantic, 웹 프레임워크와 라이브러리 버전
