# A2D 시연 진행

같은 시연을 여러 번 똑같이 찍기 위한 순서다. 모든 명령은 저장소 루트의 [`a2d-demo.sh`](../a2d-demo.sh)로 한다. 피공격 서버만 다룰 때의 세부 명령은 [target/README.md](../target/README.md)에 있다.

```
[처음 한 번] 준비 ─▶ [테이크] reset → 등록 → verify → 점검 1 → fix → 점검 2 → test-server on → 점검 3 ─┐
                         ▲                                                                       │
                         └──────────────────────────── 다음 테이크 ───────────────────────────────┘
```

## 1. 처음 한 번: 준비

인터넷이 되는 곳에서 끝내 둔다. 그 뒤로는 오프라인에서도 테이크를 반복할 수 있다(LLM을 쓰면 VPN만 필요하다).

1. `cp apps/api/.env.example apps/api/.env` 하고 아래 값을 확인한다.

   | 키 | 값 |
   | --- | --- |
   | `A2D_ADMIN_EMAIL`, `A2D_ADMIN_PASSWORD` | 시연 계정. 화면에서 이 값으로 로그인한다 |
   | `A2D_VERIFY_MODE` | `dns`(기본). `trust`면 TXT 확인 없이 통과한다. 손으로 바꾸지 말고 `./a2d-demo.sh txt-check on\|off`로 바꾼다 |
   | `A2D_WEB_ORIGIN` | `http://localhost:4173`이 들어 있어야 한다(기본값에 있다). 없으면 로그인부터 403이다 |
   | `A2D_ENGINE` | `fixture`(기본). 아래 3절대로 시나리오가 정해진다 |

2. `./a2d-demo.sh up`: 피공격 서버 이미지, 백엔드 이미지, 화면 의존성을 받고 화면을 빌드한다. 처음에는 몇 분 걸린다.
3. LLM을 쓸 때만: VPN을 연결하고 다른 터미널에서 `model/llm.sh tunnel`을 연다. `./a2d-demo.sh status`가 이 PC에 맞는 `A2D_LLM_BASE_URL`과 `model/.env`의 `TUNNEL_BIND`를 알려 준다. 넣은 뒤 `(cd apps/api && docker compose up -d)`로 백엔드만 다시 띄우고 `status`에서 `LLM: up`을 확인한다.
   - GPU 서버는 11월 1일(일) 13:00에 삭제된다. LLM이 나오는 영상은 그 전에 찍는다([model/README.md](../model/README.md)).
4. 브라우저: 시연 전용 창(새 프로필 또는 시크릿 창)을 쓰고, 창 크기와 확대 비율(100%)을 정해 두고 테이크마다 같게 둔다. 화면은 라이트 모드로 고정돼 있다.
5. 리허설로 2절의 테이크를 한 번 끝까지 해 본 뒤 `./a2d-demo.sh reset`.

## 2. 테이크마다

시작 전에 `./a2d-demo.sh reset`을 하고, `./a2d-demo.sh status`가 `시연 진행: 도메인 등록 전`인지 본다. 브라우저는 `http://localhost:4173/login`을 새로 연다(reset 전의 세션은 끊겼다).

| # | 화면에서 | 터미널 | 보여야 할 것 |
| --- | --- | --- | --- |
| 1 | 로그인 | | 도메인이 없어 등록 화면으로 간다 |
| 2 | 도메인 `jobnest.test` 입력 → 다음 | `./a2d-demo.sh verify` | TXT 이름·값. 스크립트가 백엔드에서 값을 읽어 시연 DNS에 넣는다 |
| 3 | 확인 → 점검 시작 | | 소유권 확인됨, 점검 진행 막대 |
| 4 | (점검 1이 끝날 때까지 대기) | | 안전 점수 20 F, 오늘 할 일 #16 → #8 → #18. 조치 가이드: LLM이면 "AI 설명", 아니면 "기본 가이드" |
| 5 | 조치 가이드, 질문하기 | `./a2d-demo.sh fix 16 8 18` | 피공격 서버의 세 결함이 고쳐진다 |
| 6 | 재점검 | | 100 A, 해결됨 3건. 기록 화면에 점수 추이 |
| 7 | | `./a2d-demo.sh test-server on` | `test.jobnest.test`가 새로 열린다 |
| 8 | 재점검 | | 새 노출 자산·새 발견 알림, #19 발견, 53 D |

어느 단계에서든 `./a2d-demo.sh status`가 다음 점검이 몇 회차이고 그 전에 무엇을 할지 알려 준다.

TXT 장면을 빼고 찍을 때는 테이크 전에 `./a2d-demo.sh txt-check off`를 한다. 2단계의 `verify` 없이 3단계에서 "확인"만 누르면 통과한다. 다시 켜려면 `./a2d-demo.sh txt-check on`. 둘 다 백엔드만 다시 띄우므로 로그인이 풀리고 점검 기록은 남는다. `status`에 지금 상태가 나온다.

## 3. 결과가 매번 같은 이유와 어긋나는 경우

기본 점검 엔진(`fixture`)은 피공격 서버에 점검 요청을 보내지 않고 [시나리오](../apps/api/fixtures/demo_engine.json)를 돌려준다. **이 도메인에서 끝까지 돈 점검이 몇 번째인지**로 결과가 정해진다.

| 회차 | 결과 |
| --- | --- |
| 1 | #16 #8 #18, 20 F |
| 2 | 세 가지 해결, 100 A |
| 3 이후 | 새 테스트 서버, #19, 53 D (4회차부터는 3회차를 반복) |

- 피공격 서버를 고쳤는지는 보지 않는다. `fix`·`test-server on`은 서버가 실제로 바뀌는 장면을 위한 것이고, 점수는 회차가 정한다. 그래서 점검을 순서보다 한 번 더 누르면 다음 장면이 당겨진다. 대시보드의 "재점검"과 조치 가이드의 "고친 뒤 재점검"은 둘 다 점검 1회다.
- 중지한 점검은 세지 않는다. 잘못 누른 점검은 끝나기 전에 중지하면 회차가 그대로다. 다만 기록 화면에 중지된 점검이 한 줄 남으므로, 영상에 남기 싫으면 `reset`한다.
- target/README의 "하나씩 고치면 30 F → 49 D → 100 A"는 실제 점검 엔진을 붙여야 나온다. fixture에서는 2회차가 바로 100 A다.
- 회차는 도메인마다 센다. 화면의 도메인 추가로 다른 도메인을 등록하면 그 도메인은 1회차부터다. 시연은 `jobnest.test` 하나로 한다.
- TXT 값은 등록할 때마다 새로 나온다. reset 뒤에는 2단계의 `verify`를 꼭 한다(TXT 확인을 끈 `txt-check off` 상태면 생략한다).
- LLM을 쓰면 조치 가이드와 답의 문장이 테이크마다 조금 다를 수 있다. 점수·순서·발견·조치 단계는 같다. 근거 검증에 실패한 항목은 기본 가이드 문장으로 나간다.

`reset`이 하는 일:

| 지운다 | 되돌린다 | 그대로 둔다 |
| --- | --- | --- |
| 점검 기록, 등록 도메인, 로그인 세션, 로그인 잠금 | 결함을 시연 프로필(#16 #8 #18만 결함)로, 테스트 서버 닫힘 | 이미지, 화면 빌드, `apps/api/.env`, LLM 설정과 터널 |

`up`은 점검 기록을 지우지 않는다. 지난 테이크 기록이 남아 있으면 `up`이 경고하니, 처음부터 하려면 `reset`을 한다.

## 4. 실수했을 때

| 상황 | 할 일 |
| --- | --- |
| 점검을 한 번 더 눌렀다 | 끝나기 전이면 중지한다. 이미 끝났으면 회차를 되돌릴 수 없으니 `reset` 후 처음부터 |
| "확인"을 눌렀더니 "TXT 레코드 값이 발급한 값과 다릅니다" | reset 전 값이 시연 DNS에 남아 있다. `./a2d-demo.sh verify` 후 다시 "확인" |
| 로그인이 `403`(허용되지 않은 화면) | 연 주소가 `A2D_WEB_ORIGIN`에 없다. `localhost`와 `127.0.0.1`도 다른 주소로 본다 |
| 비밀번호를 5번 틀려 잠겼다 | 5분 기다리거나 `reset`(잠금은 백엔드 메모리에 있다) |
| 조치 가이드가 "기본 가이드" | LLM이 꺼져 있거나 응답하지 않았다. `status`로 확인한다. 가이드는 점검이 끝날 때 만들어지므로 LLM을 붙인 뒤의 다음 점검부터 바뀐다 |
| 질문하기가 "지금은 AI 답변을 받을 수 없습니다" | 위와 같다 |
| 점검이 "조치 가이드 작성 중"에서 오래 걸린다 | LLM이 느리다. 최대 150초 뒤 기본 가이드로 끝난다 |

## 5. 끝낼 때

`./a2d-demo.sh down`으로 화면·백엔드·피공격 서버를 내린다. 점검 기록은 남으므로 다음에 이어서 하려면 `up`, 처음부터 하려면 `up` 뒤 `reset`.
